# Tier 企业 RAG 第一轮安全测试报告

测试日期：2026-08-28  
测试范围：FastAPI 网站、登录会话、管理员 API、资料权限、在线来源、文件解析、模型配置、RAG 提示词边界  
测试方式：代码审计、自动化恶意输入测试、正式环境低风险黑盒验证

## 结论

服务器共通过 42 项自动化测试。未登录越权、伪造 Cookie、跨站写请求、模型地址 SSRF 和提示词泄密请求均在正式环境被拦截。服务、ClickHouse 和知识库保持健康。

本轮没有执行密码爆破、并发压测、拒绝服务、大文件实际解压、破坏性文件操作或第三方基础设施扫描。

## 已修复

| 风险 | 修复 |
|---|---|
| 缺少浏览器安全响应头 | 启用 CSP、DENY frame、nosniff、no-referrer、Permissions-Policy 和敏感页面 no-store |
| 跨站请求伪造 | 拒绝跨站来源及 `Sec-Fetch-Site: cross-site` 的写请求，保留 SameSite=Strict |
| 审计 CSV 公式注入 | 中和以 `= + - @`、制表符或回车开头的单元格 |
| 用户名计时枚举 | 不存在或停用账号执行等量 PBKDF2 密码计算 |
| 在线资料 SSRF | 拒绝本机、内网、链路本地、保留 IP、URL 内嵌凭证，并在跳转后重新校验 |
| 模型服务 SSRF | 正式环境模型主机白名单限制为已批准的公司模型地址和 OpenRouter |
| Office/图片资源炸弹 | 限制 Office 解压大小与条目数、图片像素和 PDF 页数，拒绝加密 Office 文件 |
| 文档提示词注入 | 将检索证据声明为不可信数据，禁止执行文档中的角色设定、泄密或忽略规则指令 |

## 尚未解决的高优先级事项

1. 公网仍使用 HTTP。账号密码和会话 Cookie 缺少传输层加密，`COOKIE_HTTPS_ONLY` 不能安全启用。IT 必须配置正式域名、TLS 证书和 HTTPS 反向代理，然后启用 `COOKIE_HTTPS_ONLY=true` 与 `ENABLE_HSTS=true`。
2. 管理员密码应更换为至少 16 位随机密码，并通过公司密码管理器保存。不要继续使用可记忆的固定短语。
3. 使用 OpenRouter 等外部模型时，员工问题和召回的公司文档片段会发送给第三方。正式公司资料应完成数据出境和供应商审批，或切回公司本地模型。
4. 公网入口建议增加反向代理限流、WAF/公司 VPN、IP 访问策略和异常登录告警。当前应用内限流只能作为基础保护。

## HTTPS 上线后的配置

```text
COOKIE_HTTPS_ONLY=true
ENABLE_HSTS=true
ALLOWED_ORIGINS=https://正式域名
```

启用前必须先确认 HTTPS 正常，否则浏览器将无法发送 Secure 登录 Cookie。
